# W2.8: a system can have several points

A working note, written before the code so the next session starts from the
decision. W2.8 is "nonlinear systems: substitute the linear ones out, then a
resultant for two polynomial equations, then Newton from the remaining
candidates", and its Verify names circle ∩ line, circle ∩ circle and two conics.

## The type problem, which is the whole problem

`solve_system` returns `Vec<(SymbolId, Expr)>` — **one** assignment list, i.e. one
point. Circle ∩ line has two points; two conics have up to four. Returning one
point and calling it the answer is the mistake this project already treats as a
bug: it is a right-looking answer to a different question.

Two answers are wrong and one is right:

- *Wrong:* return the first point. (The same mistake as returning one numeric root
  of `x⁴ − x − 1`, which was fixed this session by a union.)
- *Wrong:* widen `Solutions` — that type is about the values of **one** variable.
  A system's answer is a set of assignments, not a set of numbers for `x`.
- *Right:* a new outcome, beside the existing one:
  ```rust
  /// One point of a system's answer set: every unknown pinned at once.
  pub type Point = Vec<(SymbolId, Expr)>;

  // in jobs.rs / the trait
  enum SystemAnswer { None, All, Points(Vec<Point>) }
  ```
  Additive: `Solver::solve_system` keeps its signature and its linear behaviour,
  and a new `solve_nonlinear` (default `NotImplemented`) returns `SystemAnswer`.
  The GUI adds `SolveState::Points` and renders `(x, y) = (2, 1)` per point, which
  reads the way the answer is spoken.

## The method, in the order that fails honestly

1. **Substitute the linear equations out.** `x + y = 3` is already solved by the
   existing elimination; replacing `y` with `3 − x` in the others turns two
   equations in two unknowns into one in one unknown. This reuses
   `system::substitute` and `solve_system`, not new code.
2. **Two polynomial equations in two unknowns: a resultant.** `canlab-poly`
   already has `resultant` over `Poly<C>`; eliminate one variable to get a
   univariate polynomial in the other, solve it exactly (W2.3 and W2.1's
   `Approximation`), then back-substitute to get the partner coordinate.
3. **Anything left: Newton from the candidates**, using `canlab-num`. Every
   reported point is substituted back into **all** the original equations and must
   satisfy each to a stated tolerance; the tolerance is reported with the point,
   the way a residual is reported with a root.

## The tests that must exist first

- **Circle ∩ line** — `x² + y² = 5`, `y = x + 1` → two points; both substitute to
  zero.
- **Circle ∩ circle** — `x² + y² = 4`, `(x−1)² + y² = 4` → two points, symmetric,
  and the numbers are irrational (√3-ish), so this is also the test that the
  numeric path is honest about being numeric.
- **Two conics** — up to four points, at least two found, each substituted.
- **The refusal that matters**: a system with **no** intersection (`x² + y² = 1`,
  `x² + y² = 4`) answers "none", not an empty list, and a system whose reduction
  is unsupported declines rather than returning a subset.
- **The bug the plot already had**: points must not be produced by pairing
  equations from *different* systems. The plot learned this the hard way; the
  solver's answer must be right for the same reason.

## Why not this session

The two type decisions that landed today — `Union` and `Approximation` — each
took several rounds of failing tests to get right, and each was smaller than this
one. This note exists so that work starts from a decision, with its failure modes
already named, rather than being discovered at the tail of a long session.
