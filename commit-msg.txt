Bevy owns the window, and the corpus runner exists

The stack move (W0.0): `eframe` is gone. Bevy 0.20.1 and `bevy_egui` 0.43.1 own
the window and the event loop, egui 0.36 is the interface inside it, and
`CasApp::draw(&mut Ui)` kept its signature, so the port was a boot function plus
one real fix: the job receiver is not `Sync` and a Bevy resource must be, so it
sits behind a lock that only the UI ever takes. `shot.rs`, the `glow` feature and
the `Renderer` choice retire with `eframe`; a frame is captured by the headless
harness instead.

Two things the port found silently: `bevy_egui`'s primary context lives on a
camera (without one, every frame draws nothing), and winit draws a light title
bar over a dark app unless the window asks for a dark theme.

Build time, measured rather than guessed: `debug = "line-tables-only"` cut an
incremental build from 79.7 s to 40.5 s, because debug info was most of what the
linker copied. `bevy/dynamic_linking` is documented in the manifest but not
enabled: Windows fails to link it with LNK1189 unless the performance profiles
are set too.

W0.3: `canlab bench` measures the implicit tracer, `Program::eval`,
`eval_batch` and the sampler, and writes `docs/bench.md`. On this machine:
2.18 ms per 240x240 rebuild, 50.5 ns per evaluation of a 20-node expression,
0.182 ms for 2000 sampled points.

W0.4: `canlab-corpus` implements the format in `docs/corpus.md` — the restricted
TOML subset, the action rule, batching through a child process so one crash
loses one batch, the coverage report, and fetch/update that fails honestly with
no network. Ten seeded cases, eight of them passing: the two definite integrals
wait for W3.1 and say so, which is what the spec asked for.

Plus `scripts/remote.ps1` for building on the GPU server, and lessons.md's two
new entries: the subtitle bar and the tests that only ran on a permissive
machine.
